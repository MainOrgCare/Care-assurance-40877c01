## 🧠 Technical Memory

**Critical Discoveries:**

- AI/SSE endpoints in `server/routes.ts` must never set `Access-Control-Allow-Origin: *`; streaming responses should mirror only trusted request origins (canonical domain, configured CORS origins, local dev hosts, Render API host, and extension origins) to prevent cross-origin data exposure.
- `requireAdmin` in `server/routes.ts` is the right audit choke point for admin operations: attaching a one-time `res.finish` hook there captures every mutating admin endpoint (`POST`/`PUT`/`PATCH`/`DELETE`) in `system_logs` without route-by-route duplication.
- User deletion in `server/storage.ts` must clear/null all user-linked FK references (not just sessions/consents) before deleting from `users`, because historical rows in tables like `care_worker_rotas`, `call_recommendations`, `workbook_uploads`, `emar_corrections`, and rostering `created_by` tables can otherwise trigger `23503` FK violations.
- Extension popup responsiveness depends on debounced/non-overlapping refresh orchestration: high-frequency storage updates and workspace polling should go through a scheduler (instead of direct repeated `refreshPayloadStatus` calls) and workspace/tab checks should be visibility-aware with a cooldown to avoid UI jank.
- Extension content-script dedupe guards should only be persisted after page/form preconditions are met and should be cleared on autofill failures so transient page-state mismatches do not permanently block retries in the same tab session.
- Initial Assessment autofill now depends on an explicit review-type selector mapping: `form_component_1277_1` should be filled with one of `Initial Visit / Service Setup`, `6 Monthly Review`, or `Annual Review`, and the matching conditional review-date field (`form_component_1283_1`/`form_component_1284_1`/`form_component_1285_1`) should be populated when an assessment date is available.
- Extension content scripts that reuse the same Mobizio tab across autofill runs must key any `sessionStorage` processed-guards by `queueState.batchId` as well as index/form, otherwise the next service user can be skipped as already processed when a new batch starts at index `0` in the same tab.
- Popup operations telemetry should be derived through shared state-layer builders (`popup/state.js`) and then rendered by UI modules, so command-center and diagnostics semantics stay consistent across refresh and export paths.
- Policy document uploads now share the same `.doc`/`.docx` to PDF conversion path as the main document parsing routes via `server/utils/officeToPdf.ts`; future upload changes should extend that shared helper instead of reintroducing route-local office conversion logic.
- In `render.yaml`, Render build commands must be plain YAML scalars, not double-quoted strings containing `sh -c ...`. The prior quoted form was passed through with literal outer quotes during deploy (`"sh -c ..."`), causing `command not found` before the build even started.
- `getAllDocumentContent()` from `TemporaryDataContext` returns a single combined string, not a per-document object. Feature code that treats it like `Object.values(...)` silently breaks pre-analysis and document-readiness checks.
- Render build commands in `render.yaml` must use `sh -c 'export NODE_OPTIONS=...; ...'` when chaining `npm ci && npm run build*`; inline `NODE_OPTIONS=... cmd1 && cmd2` only applies the heap override to the first command, letting Vite fall back to the runtime 512 MB limit during deploys.
- Render no longer needs a dedicated paid worker for housekeeping: the old maintenance loop now lives in `server/maintenance.ts` and is enabled from the API service with `ENABLE_BACKGROUND_MAINTENANCE=true`, so the default production blueprint is static frontend + API + database.
- Edge extension payload storage now relies on a shared freshness key (`caAcpDataTimestamp` / `STORAGE_KEYS.dataTimestamp`) across popup and background paths. Any code path that stores `caAcpPayload` must update that timestamp too, or `popup.js` will treat the payload as stale and auto-clear it on popup open.
- Extension content scripts should use `CA_EXTENSION_CONSTANTS.STORAGE_HELPERS` instead of direct `chrome.storage.local` calls for payload, queue, signature, and verification state. Those keys now live in session-backed storage, so direct local-only reads in `content-acp.js`, `content-emar.js`, `content-initial-assessment.js`, or `content-generic.js` can miss the active batch entirely.
- Postgres-backed rostering database management endpoints (`/api/admin/rostering/data-stats`, `/api/admin/rostering/workbook-uploads`, `/api/admin/rostering/cleanup-expired`, `/api/admin/rostering/reset-data`) already require `requireAdmin` on the server, and `client/src/components/rostering/AdminDatabasePanel.tsx` now also blocks non-admin rendering and disables all fetch/mutation activity unless `user.role === "admin"`.
- Mobizio content scripts share one injected JS scope on `clece.mobizio.com`, so repeated top-level `const` or `let` names across `content-acp.js`, `content-emar.js`, `content-initial-assessment.js`, and `content-generic.js` can hard-fail later scripts with `Identifier ... has already been declared`. Keep those files wrapped in IIFEs or otherwise scoped locally.
- Session-backed extension keys should be bridged through the background worker when accessed from webpage content scripts. Direct `chrome.storage.session` access from the web-page context can fail with `Access to storage is not allowed from this context`, so the shared storage helper now routes session reads and writes through runtime messages instead.
- The shared extension storage helper in `extension/edge-acp-autofill/constants.js` must catch synchronous `chrome.storage` and runtime bridge failures as soft fallbacks, because after an extension reload/update old Mobizio content scripts can continue running briefly and otherwise throw `Extension context invalidated` from overlay refresh or other storage-backed UI paths.
- The extension popup now treats in-page workflow control as a shared `Page Companion` contract: popup actions send `CA_EXTENSION_TOGGLE_OVERLAY` into the active Mobizio tab, ACP and EMAR pages respond with CareAssurance-style runtime overlays, and Initial Assessment responds by expanding its verification summary panel instead of introducing a second overlay surface.
- Extension upload mirroring now follows a direct bridge contract: popup section buckets serialize files to base64 and send `CA_EXTENSION_SEND_TO_APP` through `content-app.js`, and `client/src/context/TemporaryDataContext.tsx` imports them via `uploadFile(section, file)` so extension uploads land in the same app Upload pipeline as manual web uploads.
- ACP risk-assessment autofill in `extension/edge-acp-autofill/content-acp.js` should detect the target table and row fields from labels, headers, and nearby cell context instead of assuming Mobizio will always keep `#Table_9_9_Table` and the `form_component_10*` to `form_component_16*` field sequence stable.
- ACP risk-assessment autofill in `extension/edge-acp-autofill/content-acp.js` now fills the new Mobizio training-needs select (`form_component_35_26`) conservatively: it uses an explicit payload flag when present, otherwise defaults to `No` unless the assessment text clearly indicates extra, refresher, specialist, or otherwise non-standard-practice training is needed.
- Edge extension packaging is now centralized in `script/package-extension.mjs`, and both `npm run package:extension` and the admin rebuild/download endpoints in `server/routes/extension.ts` rely on that same script. The previous `script/package-extension.py` target did not exist, so future packaging changes must keep the Node script and admin route aligned.
- Default extension packaging is ZIP-first and must succeed without Chromium installed. `script/package-extension.mjs` now treats the CRX artifact as optional unless explicitly required, so missing Chromium should no longer surface as a packaging failure for the standard Edge ZIP workflow.
- Access Care Planning service-user imports now have a dedicated path: `shared/schema.ts` defines `access_care_planning_service_users` and `script/importAccessCarePlanningServiceUsers.ts` parses an `.xlsx`, extracts a service-user name plus numeric ACP ID from the adjacent link column, ensures the table exists, and upserts the mapping into Postgres.
- README documents a mature multi-domain healthcare operations platform rather than an early MVP scaffold.
- Route-level frontend code-splitting + idle preloading already implemented for common pages.
- Security posture is explicitly engineered (canonical host controls, CSRF/origin checks via route stack, progressive lockout helpers, request logger middleware).
- Extension supports two workflows: traditional payload autofill + direct document upload for AI analysis.
- `server/routes.ts` contains a local `PIIVault` implementation; helper integrations should use structural typing for vault compatibility instead of concrete class coupling.
- Long-running client AI SSE requests can exceed the default 30-second API timeout. `client/src/main.tsx` now extends any `/api` request that advertises `Accept: text/event-stream` to a 180-second timeout, and `client/src/pages/service-users/RiskAssessment.tsx` explicitly marks its streamed AI analysis/generation requests that way.
- Risk assessment generation on `POST /api/ai/generate-risk-assessment` now degrades to the existing rule-based generator when the AI completion fails or returns unparsable JSON, so generation still completes instead of ending the SSE stream with a generic `AI generation failed` error.
- Risk workflow prompts that embed policy/template context or analysis summaries into the AI `systemPrompt` must scrub those fragments with the route-local `PIIVault` before calling `executeSecureTextCompletion`; the secure helper only scrubs the user payload, so unsanitized system-prompt context can still trigger `PII detected in AI prompt` blocks in `createChatCompletionWithLogging`.

- Message routes return the standard `apiSuccess` envelope, so client code that uses manual `fetch` must unwrap responses with `parseApiResponse` or `normalizeApiPayload` instead of assigning raw `res.json()` into array state.
