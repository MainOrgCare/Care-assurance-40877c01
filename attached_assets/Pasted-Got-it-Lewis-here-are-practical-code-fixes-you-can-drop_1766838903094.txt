Got it, Lewis—here are practical code fixes you can drop in to resolve **React error #31 (“Objects are not valid as a React child”)**. This happens when an **object like `{ name, relationship, phone }` is rendered directly in JSX**.

***

## 1) You’re rendering the whole object → Render its fields instead

**❌ Problematic**

```jsx
// Somewhere on your upload page
<p>{emergencyContact}</p> // emergencyContact is an object
```

**✅ Fix**

```jsx
<p>Name: {emergencyContact?.name}</p>
<p>Relationship: {emergencyContact?.relationship}</p>
<p>Phone: {emergencyContact?.phone}</p>
```

If `emergencyContact` may be `null/undefined`, use optional chaining or guard:

```jsx
{emergencyContact && (
  <>
    <p>Name: {emergencyContact.name}</p>
    <p>Relationship: {emergencyContact.relationship}</p>
    <p>Phone: {emergencyContact.phone}</p>
  </>
)}
```

***

## 2) You’re passing an object as **children** to a component

**❌ Problematic**

```jsx
<Label>{emergencyContact}</Label>  // children receives an object -> crash
```

**✅ Fix – pass a string or element**

```jsx
<Label>
  {`${emergencyContact.name} (${emergencyContact.relationship}) — ${emergencyContact.phone}`}
</Label>
```

**Better: use a prop instead of children**

```jsx
// Component
function ContactLabel({ contact }) {
  return (
    <span>
      {contact.name} ({contact.relationship}) — {contact.phone}
    </span>
  );
}

// Usage
<ContactLabel contact={emergencyContact} />
```

***

## 3) You’re rendering a **list/array of objects** (e.g., multiple contacts)

**❌ Problematic**

```jsx
<ul>{emergencyContacts}</ul> // emergencyContacts = [{...}, {...}]
```

**✅ Fix – map to elements**

```jsx
<ul>
  {emergencyContacts.map((c) => (
    <li key={c.phone}>
      <strong>{c.name}</strong> — {c.relationship} — {c.phone}
    </li>
  ))}
</ul>
```

If the object’s keys are dynamic or you just need a quick debug display:

```jsx
<pre>{JSON.stringify(emergencyContact, null, 2)}</pre>
```

*(Good for debugging; format the UI properly for production.)*

***

## 4) You’re putting objects into **state** and rendering them directly

**❌ Problematic**

```jsx
const [status, setStatus] = useState(null);
setStatus({ name, relationship, phone });

// Later in render
<div>{status}</div> // Boom: object as child
```

**✅ Fix**

```jsx
<div>
  {status && (
    <>
      <div>Name: {status.name}</div>
      <div>Relationship: {status.relationship}</div>
      <div>Phone: {status.phone}</div>
    </>
  )}
</div>
```

Or format a message when setting:

```jsx
setStatus(`${name} (${relationship}) — ${phone}`);
```

***

## 5) Defensive helper for rendering unknown objects

If you have multiple places where a value might be string/number/object:

```jsx
function renderValue(v) {
  if (v == null) return null;
  if (typeof v === 'string' || typeof v === 'number') return v;
  return <pre>{JSON.stringify(v, null, 2)}</pre>;
}

// Usage:
<div>{renderValue(emergencyContact)}</div>
```

**❌ Before**

**✅ After**

## 7) (Optional) TypeScript guard to prevent this at compile time

```ts
type EmergencyContact = {
  name: string;
  relationship: string;
  phone: string;
};

type Props = { emergencyContact?: EmergencyContact | null };

const EmergencyContactCard: React.FC<Props> = ({ emergencyContact }) => {
  if (!emergencyContact) return null;
  const { name, relationship, phone } = emergencyContact;

  return (
    <section aria-label="Emergency contact">
      <h4>Emergency Contact</h4>
      <p><strong>{name}</strong></p>
      <p>{relationship}</p>
      <p>{phone}</p>
    </section>
  );
};
```
